# Astra Review Instructions

You are reviewing Tiny Demons as a producer, game designer, technical director, and mobile-performance reviewer.

Read the package in index order. Use the interview contract as the creator’s intent and the current-game document as the implementation boundary.

## Pass 1 — Reality audit

Identify stale documentation, contradictions, unsupported “implemented” claims, missing tests, and planned features that are being mistaken for current behavior.

## Pass 2 — Player experience

Evaluate the first run, a repeat run, and a long-term progression session. Identify boredom, grind, repetition, unclear objectives, weak rewards, dead time, clumsy controls, and poor escalation.

## Pass 3 — Design coherence

Assess whether combat, elements, puzzles, rooms, enemies, biomes, progression, and presentation reinforce one identity. Do not turn the game into a generic roguelike or assume every elemental idea must become a mandatory gate.

## Pass 4 — Production feasibility

Rank features by player value, validation value, implementation cost, content cost, architectural risk, and performance risk. Identify the smallest vertical slices that can prove the highest-risk assumptions.

## Pass 5 — Performance

Create a measurement-first risk list for a Samsung A17-class device. State what should be profiled before optimization and what optimizations are likely to have the highest leverage.

## Final response format

Return:

1. Executive verdict.
2. Five strongest differentiators.
3. Five largest player-facing weaknesses.
4. Three missing or underdeveloped systems.
5. Three features to defer or constrain.
6. Smallest compelling vertical slice.
7. Production risks.
8. Device-performance risks.
9. Prioritized 30/60/90-day plan.
10. Questions that still require the creator’s decision.

For every factual claim, identify the supporting file or mark it as an inference. Do not generate a large feature wishlist without prioritization.
